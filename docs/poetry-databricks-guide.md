# Using Poetry with Databricks Serverless

This guide explains how to use Poetry for package management in Databricks serverless environments.

## Why Poetry?

Poetry provides better dependency management compared to requirements.txt:
- **Dependency resolution**: Automatically resolves conflicts between package versions
- **Dependency groups**: Separate production, development, and optional dependencies
- **Lock file**: Ensures reproducible builds across environments
- **Smaller footprint**: Install only what you need for each environment

## Project Structure

```
pyproject.toml          # Poetry configuration with all dependencies
poetry.lock             # Locked versions (generated by Poetry)
requirements.txt        # Lightweight requirements for Databricks (generated from Poetry)
```

## Using Poetry Locally

### Install Dependencies

```bash
# Install only core production dependencies
poetry install --only main

# Install with visualization dependencies
poetry install --with viz

# Install everything including dev dependencies
poetry install --with viz,dev

# Install all optional dependencies
poetry install --extras all
```

### Add New Dependencies

```bash
# Add a core production dependency
poetry add package-name

# Add a visualization dependency
poetry add --group viz package-name

# Add a dev dependency
poetry add --group dev package-name
```

### Update Dependencies

```bash
# Update all dependencies
poetry update

# Update a specific package
poetry update package-name

# See what would be updated
poetry update --dry-run
```

## Using with Databricks Serverless

### Method 1: Export requirements.txt (Recommended)

Generate a lightweight requirements.txt for Databricks:

```bash
# Core dependencies only (smallest footprint)
poetry export -f requirements.txt --without-hashes --only main -o requirements.txt

# With visualization dependencies
poetry export -f requirements.txt --without-hashes --only main --with viz -o requirements.txt

# With all dependencies
poetry export -f requirements.txt --without-hashes --extras all -o requirements.txt
```

Then use this requirements.txt in your Databricks workflow configuration.

### Method 2: Build and Upload Wheel

For more advanced use cases, build a wheel package:

```bash
# Build wheel
poetry build

# The wheel will be in dist/fashion_recommendations-0.1.0-py3-none-any.whl
```

Upload to Databricks and reference in your job configuration:

```yaml
libraries:
  - whl: /Workspace/path/to/fashion_recommendations-0.1.0-py3-none-any.whl
```

## Databricks Workflow Integration

### Current Setup (requirements.txt)

Your workflows currently use requirements.txt. To minimize package installation:

1. **For model training notebooks** (serverless compute):
   ```bash
   poetry export -f requirements.txt --without-hashes --only main -o requirements.txt
   ```
   This includes only core ML dependencies (mlflow, pandas, numpy, scikit-learn).

2. **For analysis notebooks** (with visualizations):
   ```bash
   poetry export -f requirements.txt --without-hashes --only main --with viz -o requirements-viz.txt
   ```
   Reference this in notebooks that need plotting: `%pip install -r requirements-viz.txt`

### Updating databricks.yml

If your notebooks need different dependency sets, you can specify them in the workflow:

```yaml
tasks:
  - task_key: train_model
    notebook_task:
      notebook_path: ../training/notebooks/train_popularity.py
    # Serverless compute automatically uses requirements.txt if present

  - task_key: analysis_notebook
    notebook_task:
      notebook_path: ../training/notebooks/analysis.py
    libraries:
      - requirements: requirements-viz.txt  # If you need visualization dependencies
```

## Best Practices for Databricks Serverless

### 1. Keep Dependencies Minimal

Databricks serverless environments already include many common packages. Only install what's missing:

```bash
# Check what's pre-installed in Databricks Runtime
# See: https://docs.databricks.com/release-notes/runtime/index.html
```

### 2. Use Specific Version Constraints

Be explicit about version ranges to avoid surprises:

```toml
[tool.poetry.dependencies]
mlflow = "^3.0.0"  # Allows 3.x.x
pandas = "~1.5.0"  # Allows 1.5.x only
```

### 3. Separate Analysis from Training

Training notebooks should use minimal dependencies:
```bash
poetry export --only main -o requirements-training.txt
```

Analysis notebooks can use more:
```bash
poetry export --only main --with viz -o requirements-analysis.txt
```

### 4. Pin Critical Dependencies

For production workloads, pin exact versions using poetry.lock:

```bash
poetry export -f requirements.txt --without-hashes --only main -o requirements.txt
```

This ensures the exact versions from poetry.lock are used.

## Common Workflows

### Updating Your Environment

```bash
# 1. Add or update dependencies in pyproject.toml
poetry add new-package

# 2. Update lock file
poetry lock

# 3. Export for Databricks
poetry export -f requirements.txt --without-hashes --only main -o requirements.txt

# 4. Deploy to Databricks
databricks bundle deploy
```

### Adding a New Model Library

```bash
# Add to core dependencies (if needed in production)
poetry add tensorflow  # or torch, xgboost, etc.

# Export updated requirements
poetry export -f requirements.txt --without-hashes --only main -o requirements.txt
```

### Testing Locally Before Deploying

```bash
# Install with dev dependencies
poetry install --with dev

# Run tests
poetry run pytest

# If tests pass, export and deploy
poetry export -f requirements.txt --without-hashes --only main -o requirements.txt
databricks bundle deploy
```

## Troubleshooting

### Poetry Lock Takes Too Long

```bash
# Clear Poetry cache
poetry cache clear pypi --all

# Try with verbose output
poetry lock -vvv
```

### Dependency Conflicts

```bash
# Show dependency tree
poetry show --tree

# Update specific package
poetry update problematic-package

# Force resolve
poetry lock --no-update
```

### Databricks Can't Find Package

Ensure the package is exported to requirements.txt:

```bash
poetry export -f requirements.txt --without-hashes --only main -o requirements.txt
cat requirements.txt  # Verify package is listed
```

### Environment Mismatch

Keep Python versions in sync:
- pyproject.toml: `python = ">=3.11,<3.13"`
- Databricks Runtime: Use DBR 14.3+ (Python 3.11) or DBR 15+ (Python 3.12)
